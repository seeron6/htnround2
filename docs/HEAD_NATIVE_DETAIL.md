# Native video detail and hair-edge color

The native extraction step had a reproducible color error at transparent cutout boundaries. It resized the registered RGB, including zero-valued background, before applying a low-frequency color correction to the native video. This manufactured dark fringes around hair and alpha holes. Separately, the registered binary mask already excludes some visible native wisps. Fixing color fusion cannot recover those missing pixels.

## Measured defect and correction

At native coordinate `(160,317)` in `frame_0032.png`, the video RGB is `(171,167,152)`, while the previous opaque extraction is `(55,50,45)`. Alpha-normalized resampling and color correction produce `(155,142,125)`. The intended reference is the registered browser color, which differs from OpenCV's video decode; the native RGB is not an intrinsic skin-color ground truth.

`scripts/detail_color.py` resamples premultiplied registered RGB and divides by resampled alpha. It then estimates a smooth registered-minus-native correction using only retained foreground support. The source alpha is resized exactly as before. Hidden registered pixels and native pixels outside that alpha cannot tint the foreground correction. Complete opaque interiors retain the previous calculation byte for byte. A downscaled nearest-neighbor alpha image can erase a source hole, so nonopaque downscaled inputs instead use normalized area resampling without reusing the legacy interior calculation. Regressions cover both a disappearing hole and sparse foreground lost by decimated bilinear sampling.

The standard and streamed extraction paths both call the shared helper. Fresh extractions record version 3 and a per-frame fusion audit. Version 2 caches remain unchanged: glasses references and semantic analyses are tied to their exact image bytes. An existing capture therefore needs an explicit verified migration, not an automatic color-cache overwrite. Frames without any usable opaque foreground are skipped instead of passing a NaN matching score.

There is a remaining visual limitation: some retained binary-mask pixels mix actual hair and background in the native recording. The corrected cutout can reveal a lighter, stepped border there. This method neither estimates fractional alpha nor separates foreground/background colors. Do not describe it as recovered hair, decontaminated pixels or a photorealism improvement on every input.

## Validation

Synthetic regressions vary hidden source colors and native backgrounds, include internal alpha holes, retain native strand contrast and verify exact alpha and opaque-interior preservation. Dimension rounding follows the existing frame matcher's tolerance. A real-recording integration test compares the complete manifests and every PNG from the standard and streamed decoders; both produce byte-identical outputs. The final measured calls took 44.2 seconds and 3.9 seconds, respectively, with other local work running. An earlier pass took 32.9 and 2.7 seconds. These are extraction timings, not full reconstruction timings.

Local evidence includes `.local/detail-color-accel-tests.log`, `.local/detail-color-targeted-tests.log`, and `.local/native-detail-color-comparison.png`. The private full-material comparison is documented in `.local/native-detail-color-verification.json`; it holds geometry and semantic annotations fixed and locally re-registers the existing estimated glasses-cleanup images. It makes no new AI requests. This controlled comparison does not validate stale annotations for an automatic cache migration.

The private full-material pair was based on generation `7f1a70cdf531445184ac404d4b4e817a`. All 51 native images preserve alpha and complete opaque interiors exactly, and both bakes preserve the same float32 mesh coordinates and 1,816,104 protected prepared-color samples. Their times were 127.9 and 130.9 seconds. The baseline PNG exactly matches that published generation. Source inputs and relevant code remained unchanged during those bakes. The subsequent downscale-only fix reproduces all 51 candidate PNGs and the manifest exactly (`.local/detail-color-downscale-isolation.json`).

Re-registering an existing generated cleanup image is a real confound: the front reference's maximum corner shift changes from 14.72 to 3.67 pixels, despite identical camera coordinates and alpha. Its SIFT matches depend on the corrected RGB. This pair therefore tests the combined extraction-and-local-cleanup-registration path, not isolated native color fusion. `.local/native-detail-color-pixel-audit.json` records the reference and output differences. Existing version-2 caches are deliberately retained until a complete input migration is reviewed. A second private comparison freezes the previously validated cleanup pixels and their identical masks/crops to isolate color fusion; that experimental override is not a production cache shortcut.

With cleanup pixels, masks and crop transforms held fixed, the second pair takes 35.48 and 35.29 seconds. Its accelerated baseline is byte-identical to the published PNG. The color-only candidate changes 552,068 atlas pixels; average channel difference among changed pixels is 1.40, with a maximum of 51. Both preserve geometry and all 1,816,104 protected prepared-color samples; relevant code stays unchanged. Browser inspection covers the isolated front and -68-degree views, and both profiles/rear in the full registration pair. The ear crescent remains visible in baseline and candidate, and the native binary cutout retains its lighter stepped edge. No new release or input-cache migration was published. Evidence: `.local/detail-color-fixed-cleanup-verification.json`; review: `/hair-review.html?review=detail-color-isolated-review`.
